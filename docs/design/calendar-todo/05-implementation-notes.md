## Schema → contract map (`schemas.py`)

`TodoOut`, `EventOut`, `ReminderOut`, `Assumption`, `ReminderIn`, `TodoCreate`,
`TodoCreated`, `TodoParse`, `ParseResult`, `ParseCandidate`, `ErrorDetail`,
`TodoList`, `TodoUpdate`, `EventList`, `ReminderFeedItem`, `ReminderFeed` — all
present, pydantic v2, response models use `ConfigDict(from_attributes=True)`.
Naive datetimes rejected (422); offset-aware normalized to UTC; `lead_time`
round-trips as ISO-8601 duration (`P1D`/`PT2H`).

## Model → data-model map (`models.py`, 03-data-model §3)

`Todo`, `Event`, `Reminder`, `ReminderDelivery` — typed `Mapped`/`mapped_column`,
tz-aware UTC datetimes, FK cascades (`todos.event_id SET NULL`;
`reminders.{todo_id,event_id} CASCADE`; `reminder_deliveries.reminder_id CASCADE`),
indexes incl. the `ix_reminders_status_fire_at` scan index, CHECK constraints,
`uq_todos_event_id`, `uq_reminder_deliveries_reminder_id_channel`. Registered in
`src/migrations/env.py`.

## Parser (`parser/`, 02-architecture §4)

- `base.py` — `Parser` Protocol + `RawExtraction` + typed exceptions
  (`ParserUnavailable`/`ParseTimeout`/`ParseFailed`).
- `ollama_parser.py` — default, async `ollama` client, `format=json`, short
  `keep_alive`, bounded timeout, one call per parse. Only place `ollama` imported.
- `claude_parser.py` — optional cloud fallback via `httpx`, config-selected only.
- `resolver.py` — `dateparser` (TH+EN), `TIMEZONE=Asia/Bangkok`,
  `PREFER_DATES_FROM=future`, `RELATIVE_BASE=now`, resolves to UTC; runs off the
  event loop via `asyncio.to_thread` in the service. Date-only → `all_day` (OQ-4).
- `factory.py` + `deps.py` — select impl from `CALENDAR_PARSER`; parser outage
  degrades only `/parse` (503), app still boots (NFR-7/14/17).

## Deviations from contract (justified)

1. **Migration hand-authored, not autogenerated.** No Postgres/Docker was
   reachable in the stage-05 sandbox, and Alembic autogenerate requires a live DB
   at `head`. The migration (`a1b2c3d4e5f6_...`) was written by hand to mirror the
   models exactly and was validated by: (a) compiling `CreateTable` against the
   psycopg dialect, (b) `alembic upgrade --sql` offline generation, (c) confirming
   constraint/index names match the model-generated names 1:1. FK create order is
   `events → todos → reminders → reminder_deliveries` per 03 §9.2. **Deploy must run
   `cd src && uv run alembic upgrade head` against the real DB.**
2. **CHECK constraint names** are declared in the models as the bare suffix
   (`name="status"` etc.) so the core naming convention yields the intended
   `ck_reminders_status` (passing the full name would double the prefix to
   `ck_reminders_ck_reminders_status`). The migration mirrors this.
3. **Thai colloquial time phrases** (e.g. `3 โมงเย็น`) are not resolved by
   `dateparser` in one shot; the hybrid relies on the SLM normalizing to a cleaner
   phrase (`พรุ่งนี้ 15:00`), which resolves correctly. Unresolvable phrases hit
   the ambiguity contract (422 + candidate), never a fabricated time (FR-9a). This
   is within the stage-01 OQ-10 accuracy caveat; flagged for stage 06.
